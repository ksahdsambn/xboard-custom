# Xboard Android APP AI 开发实施计划

## 1. 文档定位

本文档是 android-app-requirements.md 的串行实施计划，面向可长期无人值守执行的 AI 开发者。本文只描述工作指令、交付物、验证方法和放行条件，不提供任何实现代码。

实施计划版本为 1.1.0。2026-09-04 已完成三轮复核，复核所针对的需求文件 SHA-256 为 8E2521ABC361204E5183F480C179E2DF2819EE18937132FBC0557BFF1742C8F1。需求文件内容或哈希变化后，本复核结论自动失效，必须重新执行三轮审查。

本文档以以下基线为准：

- xboard-custom：1fe92b1e72aedd1a667a764384266face8576124。
- Xboard master：4f48e61a2cbc6db5338872b6bdb45ef954ec1256。
- Xboard compose：0a749681bb10056bd60ebe9afe4e8928ff19210c。
- libXray：15e88365296a6f955e5e38caa2d02c97b499733f。
- Xray-core：v26.7.28，对应提交 5ca6f4b7d4dc20a881d4330e498892697627ec0c。
- 需求版本：2.0.0，Android 1.0 开发基线。

任何基线发生变化时，必须先执行本文的上游兼容审查任务，不得直接沿用旧结论。

## 2. 已核实的仓库事实

- xboard-custom 当前保存 StripePayment、BepusdtPayment、WalletCenter、自定义主题、overlay 部署脚本和少量运行时回归测试；当前没有 MobileApp 插件，也没有 xboard-mobile 客户端仓库。
- xboard-custom 当前 HEAD 与需求记录的审查基线一致；工作树中已有用户维护的未提交文档变更，执行者必须保留并避让，禁止擅自清理。
- Xboard 官方插件从 plugins 目录加载；安装和升级阶段运行插件迁移，启用及运行初始化阶段加载插件路由、命令、服务提供者、视图和启动逻辑；插件 API 路由只自动附加 API 中间件，不自动附加官方 API 版本前缀。
- Xboard 官方用户鉴权使用 Sanctum；现有用户中间件会把未登录或会话过期返回为 HTTP 403。MobileApp 必须增加稳定机器错误码，以便客户端只把真正的会话失效映射为重新登录。
- AuthService 同时返回订阅令牌和 Sanctum Bearer 会话。移动客户端只能使用 Bearer 会话访问 Mobile API，禁止把订阅令牌作为登录凭证。
- ServerService 的当前用户可用节点结果已经执行用户分组、显示状态、流量上限、排序、动态端口和用户凭证生成。MobileApp 必须以该结果为授权集合继续筛选，禁止按节点主键绕过它。
- 官方 NodeResource 只提供节点摘要，不提供建立 Reality 连接所需的完整参数。MobileApp 必须在已授权集合内通过独立适配器组装版本化 Profile，并严格排除 Reality 私钥。
- 官方 Server 模型已具有 Reality、uTLS、指纹、网络和 VLESS flow 等配置来源；Profile Schema 1 所需 SpiderX 仍须由 MobileApp 固定为根路径。
- 当前 deploy-overlay.sh 只同步三个现有插件和自定义主题，尚未同步、安装、迁移、启用或健康检查 MobileApp。
- 官方 master 在 2026-09-04 仍指向上述审查提交，compose 分支指向上述 compose 审查提交；实际部署镜像摘要仍必须由实施环境单独解析和锁定。

## 3. 全局执行纪律

- 必须严格按任务编号串行执行。不得并行修改相互依赖的服务端契约、客户端模型、支付状态或 VPN 状态机。
- 每个任务开始前，必须确认上一任务的放行记录为“通过”；没有记录、证据不完整或存在失败项，都视为未通过。
- 每个任务只能处理其明确列出的范围。发现额外需求时，先写入风险与待办记录，不得顺手扩大实现范围。
- 每个任务完成后必须保存：变更摘要、受影响文件、测试环境、测试数据、开始与结束时间、测试结果、失败与修复记录、产物校验和及最终结论。
- 自动化测试必须保存机器可读结果；真机、Google Play、长稳和合规测试必须保存可审计证据。截图不能替代日志、状态记录或服务端审计记录。
- 不得伪造外部服务、真机、24 小时长稳、Play 测试轨道或法律审批结果。缺少设备、账号、密钥、节点、网络或人工批准时，将任务标记为“阻塞”并停止。
- 日志、截图、测试报告和诊断包必须脱敏，不得记录会话令牌、购买令牌、用户 UUID、Reality 私钥、完整 Profile、DNS 查询或访问目标。
- 任何失败必须先定位、修复并完整重跑本任务全部测试。只重跑最后一个断言不构成通过。
- 每个任务必须使用独立、可追溯的变更提交；提交前不得混入用户已有的无关改动。
- P0 是 Android 1.0 发布阻断项。P1 钱包与签到默认延期，只有在所有 P0 门禁通过且获得书面批准后才允许启用。

## 4. 统一证据和状态规则

为每个任务建立独立验收记录，状态只允许使用“未开始、执行中、阻塞、失败、通过”。验收记录至少包含以下内容：

- 任务编号和需求追踪编号。
- 输入基线和实际使用的不可变版本。
- 执行动作与交付物列表。
- 正常、异常、边界、幂等和安全测试结果。
- 失败复现、修复和完整回归结果。
- 产物位置、校验和和审查人或自动化判定主体。
- 明确的“允许进入下一任务”或“禁止进入下一任务”结论。

后续所有任务的固定门禁为：验证测试和通过标准全部满足，证据已归档，才允许进入下一项任务；未通过不得进入下一项任务。

## 5. 串行实施任务

### TASK-001 冻结需求、范围与基线

**目标**

建立唯一需求来源，防止开发过程中自行改写产品范围或使用漂移的上游版本。

**执行指令**

- 读取 android-app-requirements.md 全文，将 AND-FR-001 至 AND-FR-023、非功能门槛、更新规则、Google Play 要求和完成定义登记到追踪表。
- 记录五个源码基线、Mobile API 初始版本、Profile Schema 初始版本、Android 最低 API 26 和首发协议范围。
- 明确首发排除项：其他代理协议和传输、通用订阅导入、第二内核、tun2socks、动态内核、外部数字订阅付款入口及流量内容分析。
- 将需求变更流程固定为先更新需求、再更新追踪表、再修改实现；禁止只改实现。

**交付物**

- 需求追踪表初版。
- 基线清单与范围声明。
- 首发排除项清单。

**验证测试**

- 逐项核对 23 个功能需求均有唯一追踪行。
- 核对所有版本均为精确提交、精确版本或不可变摘要，且不存在 latest、main、master 或占位值。
- 从追踪表反查需求文档，确认没有遗漏 P0、P1、非功能门槛或禁止事项。

**通过标准**

- 需求覆盖率为百分之百；基线无动态值；范围无冲突。

**放行门禁**

验证测试和通过标准全部满足并归档证据后才允许进入 TASK-002；未通过不得进入下一项任务。

### TASK-002 固定三个仓库的职责边界

**目标**

确保定制服务端、官方底座和跨平台客户端互不污染。

**执行指令**

- 将 xboard-custom 定义为 MobileApp 插件、插件迁移、服务端测试、overlay 和需求文档的唯一仓库。
- 将 cedar2025/Xboard 定义为只读上游，不得提交项目定制代码。
- 创建独立 xboard-mobile 仓库规划，要求同时容纳 Flutter、Android、iOS、Pigeon、内核构建工具和统一版本锁；禁止拆分 Android 与 iOS 仓库。
- 记录允许修改和禁止修改的目录；对任何必须触达官方核心的提议设置架构审批门槛。

**交付物**

- 仓库职责矩阵。
- 目录所有权与禁止修改清单。
- xboard-mobile 建仓说明。

**验证测试**

- 检查三类交付物均有唯一归属且没有重复所有权。
- 模拟一次服务端插件变更、一次 Android 原生变更和一次上游升级，确认都能定位到唯一仓库。
- 检查官方 Xboard 工作树不存在定制文件或未管理修改。

**通过标准**

- 所有交付物归属唯一；官方仓库保持干净；不存在要求 Android 与 iOS 分仓的设计。

**放行门禁**

验证测试和通过标准全部满足并归档证据后才允许进入 TASK-003；未通过不得进入下一项任务。

### TASK-003 建立追踪、证据和失败停止机制

**目标**

让后续 AI 能从证据判断进度，而不是依赖自然语言自报完成。

**执行指令**

- 为每个任务建立验收记录模板和机器可读状态索引。
- 为每个需求建立“需求—服务端—客户端—自动化测试—真机测试—发布证据”的双向映射。
- 定义失败处理流程：记录期望、实际、复现条件、脱敏日志、根因、修复和完整重测。
- 配置流水线在上一任务不是“通过”时拒绝后续阶段。

**交付物**

- 任务状态索引。
- 验收记录模板。
- 需求双向追踪矩阵。
- 串行门禁规则。

**验证测试**

- 人为将一个前置任务标记为失败，确认后续阶段被拒绝。
- 人为移除一份测试证据，确认任务不能标记为通过。
- 从任意 AND-FR 编号正向找到实现与测试，再从任意测试反向找到需求。

**通过标准**

- 跳步、缺证据和失败状态均会可靠阻断后续执行。

**放行门禁**

验证测试和通过标准全部满足并归档证据后才允许进入 TASK-004；未通过不得进入下一项任务。

### TASK-004 准备隔离环境与外部依赖

**目标**

在开发前确认所有不可自动生成的环境、账号和测试资产可用。

**执行指令**

- 建立开发、持续集成、预发布和生产四套隔离环境，禁止共享数据库、密钥和 Play 商品环境。
- 准备 API 26 设备、当前 Android 设备、IPv4、IPv6、双栈、Wi-Fi、蜂窝网络和可控断网条件。
- 准备 VLESS + REALITY + TCP + Vision 测试节点，覆盖正确参数、错误 UUID、公钥、short ID、server name 和不可达节点。
- 准备 Google Play 企业开发者账号、服务账号、测试应用、订阅商品、许可测试账号、RTDN 通道和审核账号。
- 准备当前生产 Android 正式版、上一主要 Android 正式版、对应签名与不可变产物标识，以及当前生产后端的不可变部署身份；后续兼容测试不得用临时模拟客户端冒充正式版本。
- 如果 Android 1.0 确为不存在任何历史正式版的首个版本，或无法取得需求所要求的当前版、上一主要版真实产物，必须把需求兼容矩阵标记为阻塞并提交需求负责人裁决；在需求文档正式修订前不得自行降低、删除或伪造该门槛。
- 准备隐私政策、服务条款、客服、删号网页和地区合规责任人；缺少人工批准时不得自行推断批准。

**交付物**

- 环境与资产清单。
- 权限责任矩阵。
- 测试数据和测试账号清单。
- 缺失项阻塞报告。

**验证测试**

- 分别验证四套环境不能互相读取数据库或密钥。
- 验证每台设备、每类网络和每个测试节点可被唯一识别并记录系统版本。
- 在不暴露密钥的前提下验证 Play Developer API 和 RTDN 测试链路的最小连通性。
- 核对当前和上一主要 Android 正式版的签名、版本、来源和校验和，并验证二者能够安装到指定兼容测试设备；缺少任一真实产物时本任务失败。

**通过标准**

- P0 所需环境全部可用；权限最小化；没有用生产密钥代替测试密钥。

**放行门禁**

验证测试和通过标准全部满足并归档证据后才允许进入 TASK-005；未通过不得进入下一项任务。

### TASK-005 复核官方 Xboard 扩展点

**目标**

把基于上游源码的事实固化为适配约束。

**执行指令**

- 复核插件安装、启用、迁移、路由、命令、计划任务、服务提供者和配置加载生命周期。
- 复核 Sanctum 会话签发、登录限制、注册规则、邮件验证码、邀请码、验证码和密码重置行为。
- 复核 UserService、PlanService、ServerService、Notice、Ticket 及相关资源和控制器的真实接口。
- 记录现有 403 会话失效、成功或失败外层语义、节点摘要缺失 Reality 参数、动态端口和用户凭证生成等兼容风险。
- 形成只通过插件适配、不得修改官方路由和核心文件的结论；无法满足时停止并提交架构阻塞报告。

**交付物**

- Xboard 适配点清单。
- 上游行为快照。
- 风险与替代方案报告。

**验证测试**

- 在干净官方基线安装一个无业务副作用的验证插件，确认路由只获得 API 中间件且需自行声明完整版本前缀。
- 验证无效 Sanctum 会话的实际 HTTP 状态和响应外层结构。
- 用同一用户对比 ServerService 授权集合与官方节点摘要，确认分组、显示、流量限制、动态端口均被保留且摘要不足以建立连接。

**通过标准**

- 所有适配假设均有源码和运行证据；不存在依赖猜测的核心扩展点。

**放行门禁**

验证测试和通过标准全部满足并归档证据后才允许进入 TASK-006；未通过不得进入下一项任务。

### TASK-006 创建 xboard-mobile 工程与统一版本锁

**目标**

建立可重复构建的跨平台客户端仓库骨架。

**执行指令**

- 创建独立 xboard-mobile 仓库，初始化 Flutter 工程、Android 与 iOS 原生目录、Pigeon 契约目录、内核构建目录、测试目录和发布证据目录。
- 固定 Flutter、Dart、Pigeon、Gradle、Android Gradle Plugin、JDK、Android SDK、NDK、Go、gomobile、libXray、Xray-core、Xboard master、Xboard compose、实际镜像摘要、Mobile API、Profile Schema 和 AAR 校验和。
- 在本任务内先按锁定源码和工具链完成一次基线 AAR 构建并写入真实校验和，TASK-007 再负责跨环境重复构建验证；禁止以待生成、未知或占位值越过本任务门禁。
- 设置 Android 最低 API 26；targetSdk 留作提审时按官方现行要求核验并锁定。
- 同一产品发布系列的 Android 与 iOS 必须锁定同一 libXray 和 Xray-core 源码提交；AAR 与 XCFramework 可以分别构建和发布，但使用不同源码基线必须先取得兼容说明和专项审批。
- 设置流水线拒绝缺失、占位、动态版本和未校验二进制。

**交付物**

- xboard-mobile 初始仓库。
- 机器可校验的统一版本锁。
- 基础持续集成流水线。

**验证测试**

- 在一台全新构建机仅依据版本锁恢复工具链并生成相同依赖解析结果。
- 将任一版本替换为动态值，确认流水线失败。
- 修改 AAR 或任一锁定产物，确认校验和验证失败。
- 对比同一发布系列的 Android 与 iOS 内核源码提交，确认二者相同；制造不一致，确认在没有专项审批时流水线失败。

**通过标准**

- 工程可重复初始化；版本锁完整；动态依赖无法进入主分支。

**放行门禁**

验证测试和通过标准全部满足并归档证据后才允许进入 TASK-007；未通过不得进入下一项任务。

### TASK-008 冻结 Flutter、Pigeon、Binder 与 VPN 进程边界

**目标**

在功能开发前固定跨层职责和版本化通信契约。

**执行指令**

- 定义 Flutter 只负责页面、导航、表单、业务状态和 Mobile API；禁止接触 TUN、文件描述符和 libXray 原始接口。

## 6. 上游更新的固定执行顺序

Android 1.0 发布后的每次 Xboard、libXray、Xray-core 或客户端升级都必须执行以下顺序，不得颠倒：

1. 创建独立升级分支，更新统一版本锁，生成变更、许可证和风险报告；上游监测只能创建报告和升级分支，禁止自动合并、自动替换生产 AAR 或自动提交商店；验证报告完整后才可继续，未通过不得进入下一项。
2. 先在预发布升级 MobileApp 或 Xboard，使后端同时兼容现有和候选客户端；运行服务端契约测试，未通过不得进入下一项。
3. 使用当前正式版和上一主要正式版验证登录、Profile、连接、权益、支付恢复和删号；任一失败不得进入下一项。
4. 将 libXray 与其实际锁定的 Xray-core 作为组合构建候选 AAR，再构建 Android 候选 APP；先过配置、适配、安全，再过真机、网络、Doze、进程、二十四小时和一百次启停，未通过不得进入下一项。
5. 完成 Google Play 测试轨道和回滚演练；Android 与 iOS 可按各自审核进度独立发布，未发布平台需要的旧契约必须继续保留。
6. 只有兼容窗口结束、活跃旧版本低于批准阈值且不存在回滚依赖后，才允许废弃旧字段或旧 Schema；条件不满足不得执行废弃。

Xboard 更新、libXray 与 Xray-core 组合更新、Android 发布是三条独立变更线。除非同一功能存在已证明且已记录的依赖，不得把三条变更线强制合并为一次生产变更。

## 7. 最终禁止事项

- 禁止跳过任务、测试、等待时长、真机验证、Play 轨道或人工合规批准。
- 禁止在任何失败、阻塞、缺证据或未知结果存在时进入下一任务。
- 禁止把项目定制代码写入 cedar2025/Xboard 官方核心。
- 禁止客户端直接依赖 Xboard 控制器响应、ORM、数据库字段、Web 页面、通用订阅文本或节点主键查询。
- 禁止客户端提交或决定套餐、用户组、流量、时长、到期时间、价格和权益。
- 禁止泄露 Reality 私钥、令牌、购买令牌、用户 UUID、完整 Profile、DNS 历史和访问内容。
- 禁止 VMess、Trojan、Shadowsocks、Hysteria、TUIC、AnyTLS、WebSocket、gRPC、XHTTP 及未批准协议或传输进入 Android 1.0。
- 禁止 tun2socks、第二内核、第二个 Go runtime、并发测速内核和运行时动态内核。
- 禁止 Google Play 发行包出现 Stripe、BEpusdt、钱包充值、余额购买订阅或外部数字订阅付款入口。
- 禁止 RTDN 直接增减权益；必须通过 Developer API 重查。
- 禁止 WalletCenter 自动续费处理活跃 Play 管理权益。
- 禁止使用 latest 或其他动态版本进行构建或生产部署。
- 禁止上游监测自动合并、自动替换生产 AAR 或自动提交 Google Play。
- 禁止依赖商店即时降级；必须使用熔断、停发和后端兼容止损。
- 禁止在未达到完成定义时宣称 Android 1.0 已完成或可上线。
